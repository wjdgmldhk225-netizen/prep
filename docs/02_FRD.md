# 카페 판매·수익·재고 관리 기능 요구사항 문서(FRD)

- 작성일: 2026-10-12
- 상태: PRD의 1차 범위를 유지한다. 남은 기능 동작·계산 선택은 사용자의 “나머지는 추천으로해줘”에 따라 아래 추천안을 채택했다.
- FRD란: 사용자가 무엇을 입력하거나 누르면 프로그램이 어떻게 처리하고 어떤 결과를 보여주는지 설명하는 문서다.
- 기준 자료: `docs/01_PRD.md`, `design/_1~_5/code.html`과 각 `screen.png`, `design/fidelity_refined/DESIGN.md`, `date/`의 제공 매장 JSON과 데이터 설명. 자료와 시안 폴더가 이동한 현재 경로를 기준으로 한다.
- 실제 수수료율 등 자료에 없는 사실은 확정하지 않는다. 2차 계산은 확장 검토안이며 1차에 구현하지 않는다.

## 1. 사용 범위와 핵심 흐름

한 매장·한 운영자가 지정한 한 기기에서 비공개로 사용한다. 제공 자료로 시작하며 판매·비용을 직접 추가·수정·삭제한다. 메뉴·재료·가격·레시피·영업달력·재고기록·월비용계획은 1차에서 조회만 한다.

## 2. 시안을 확인한 사실과 PRD의 차이

시안의 숫자·메뉴·시간은 화면 예시다. 시안 스크립트의 알림 창이나 다운로드만으로 실제 저장·발주·복원이 구현되었다고 판단하지 않는다. 이미지에는 보이지 않는 입력창과 버튼도 HTML에서 확인했다.

| 위치·확인한 내용 | PRD와의 관계 | FRD에서 채택한 처리 |
| --- | --- | --- |
| _1 기간 손익, 빠른 판매 추가, 판매 전체 보기 | 필수 기능과 연결됨 | 유지. 빠른 입력도 _5와 같은 판매 처리·검사를 사용 |
| _1 빠른 입력의 읽기 전용 판매 일시, 수수료 없는 이익 미리보기 | 날짜별 집계·수수료 보완 요구와 불일치 | 날짜 정정과 원가·수수료 확인이 가능한 공통 판매 입력을 사용. 주문 시간 입력은 추가하지 않음 |
| _5 카페라떼 5,000원·원두 18g·레시피 v2 등 | 제공 자료의 카페라떼 4,800원·원두 20g·R1 등과 다름 | 등록된 메뉴·레시피·가격으로 표시. 콜드브루·오트밀크 변경·세트 등 자료에 없는 메뉴나 옵션은 추가하지 않음 |
| _1·_3·_5 수수료 기본 3%, _5 입력 중 수수료 덮어쓰기 | 확인된 근거만 사용·직접 정정 유지 원칙과 불일치 | 고정 3% 삭제. 과거 수수료는 기록값, 새 수수료는 확인된 기준이 없으면 직접 입력. 직접 정정한 값을 자동으로 덮어쓰지 않음 |
| _5 빈 숫자를 0으로 취급, 손실을 0으로 표시 | 빈칸과 0 구분·정확한 결과 요구와 불일치 | 미입력은 미확인. 손실과 음수 재고는 그대로 표시 |
| _5 판매 작업 영역에 점 세 개만 있고 수정·삭제 동작이 명확하지 않음 | PRD의 필수 수정·삭제가 시안에 부족함 | 작업 영역에 수정·삭제 기능을 연결. 새 기능이 아니라 P02 보완 |
| _2 귀속일·8개 비용분류·금액·수정·삭제·취소·저장 | 필수 기능과 연결됨 | 유지. 귀속일과 실제 결제일을 같은 의미로 표현하지 않음 |
| _2 월 균등 배분·임시저장·부가세 자동 분리·증빙 검증·거래처·증빙 메모 | PRD에 없는 처리 또는 추가 입력 정보 | 1차에서 제외. 기존 배분기준은 조회하되 새 비용의 자동 배분은 하지 않음. 설명·증빙 등의 새 칸도 확장 후보로만 기록 |
| _2 전월 대비·계획 집행률·정상 지출 추세 | 1차에 없는 비교·판정 | 1차에서 제외. 비용 항목별 합계는 기본 비용 조회로 유지 |
| _3 목표 65%·우수 등급·사분면·전략 제언·민감도·부자재 매핑 설정 | 등급 제외·기초자료 조회 중심과 불일치 | 1차에서 제외. 메뉴별 금액과 비율만 확인 |
| _3 원가 내역 엑셀 받기, _5 엑셀 내보내기 | PRD의 입력 양식·가져오기와 다른 추가 기능 | 1차에 추가하지 않음. 보고서 내보내기는 별도 확장 후보 |
| _4 안전재고 수량 미달·소진 임박·금일 14시 고갈·발주·배송 | PRD의 현재 잔량 부족 확인 범위를 초과 | 1차는 잔량 없음·기록상 부족만 구분. 안전재고 경고·고갈시점·발주·배송 기능은 제외 |
| _4 기초+입고−소모−폐기만 있는 표 | 실사조정 항목이 빠짐 | 실사조정도 잔량에 반영하고 별도 표시. 실측수량을 다시 더하지 않음 |
| _4 실사·변동 원장 조회 | 재고기록 조회 범위와 연결됨 | 제공 기록의 날짜·부호·단위·실측수량 조회만 지원. 자료에 없는 실사자·시각은 만들지 않음 |
| 공통 저장됨·로컬 캐시 동기화, _4 100% 무손실·네트워크 자동 동기화 | 저장 상태 표현은 필요하나 클라우드 동기화는 범위 밖 | 저장 성공 때만 저장됨 표시. 동기화·무손실 보장 문구 삭제 |
| _4 JSON·prepbackup·v2.4·CRC32, 재료 잔량만 내려받는 예시 | 전체 기록 복원 요구를 충족하지 않음 | 전체 원본·수정 기록을 포함한 앱 전용 JSON 백업 사용. 형식 버전과 검사 결과는 실제 처리값으로 표시 |
| 날짜·메뉴 조회 영역이 글자만 있거나 선택칸이 없음 | 기본 조회에 필요한 조작이 부족함 | 날짜 선택칸과 조회 적용 동작을 보완. 필터·정렬 등 조회 편의 동작은 아래 범위에서만 구체화 |

사용자는 처음에 추가 기능을 개별 검토하기로 선택했고, 다음 답변에서 남은 검토를 추천안에 맡겼다. 추천 결론은 월 자동 배분 등 위 추가 기능을 1차에 넣지 않는 것이다. 일부 시안 버튼은 삭제·숨김 대상으로 기록하며, 작동하는 것처럼 남겨두지 않는다. 향후 별도 범위 확인 전에는 발주·배송 등의 새 기능을 만들지 않는다.

## 3. 기록·단위·화면 표현의 공통 기준

### 3.1 사용할 기록

- 자료는 가상 프렙 카페 샘플이다. 실적은 2025-07-01~2026-09-18, 달력은 2026-09-30까지 있다.
- 메뉴 8개, 재료 11개, 공급사 3개, 레시피 22행, 가격이력 33행, 판매 6,112건, 초기재고 11행, 재고 1,515건, 비용 3,560건, 월계획 120행, 달력 457행을 사용한다.
- 판매는 주문 한 건이 아니라 일자·메뉴·채널별 집계다. 채널은 매장·포장이다. 메뉴ID 등 같은 식별값은 같은 대상을 뜻한다.
- 판매 기록의 식재료·포장 원가는 개당 금액, 수수료·할인·순매출은 해당 집계 기록 전체 금액이다.
- 재고기록의 증감은 입고 양수·폐기 음수·실사조정 양수 또는 음수다. 실측수량은 실제로 센 양을 나타낸다.
- 비용은 귀속일별 기록이다. 월계획은 동일 비용의 참고 계획이며 비용기록과 추가 합산하지 않는다.
- 1차에는 제공 재고기록을 고치거나 추가하지 않는다. 새 입고가 없으면 앞으로의 잔량은 등록된 기록만 바탕으로 한 잔량이다.

### 3.2 공통 처리

| 상황 | 처리와 표시 |
| --- | --- |
| 날짜 | 날짜 단위로 처리하며 시작일·종료일을 모두 포함. 표시와 기간 해석은 한국 날짜 기준 |
| 돈·수량 | 돈은 원·부가세 제외. 음료 수량은 잔, 디저트는 개. 서로 합친 수량은 판매수량으로 표현. 재료별 g·ml·개는 섞어서 합산하지 않음 |
| 실제 0 | 확인되어 입력된 0은 0으로 저장·표시 |
| 빈칸 | 미입력·해당 없음 의미를 보존. 필요한 금액이 비면 원가 미확인·수수료 미확인 등 이유 표시 |
| 일부 값 미확인 | 확인된 순매출·수량은 표시. 미확인 금액을 0으로 뺀 이익은 표시하지 않음. 관련 메뉴·기간 이익은 미확인이며 누락 건수 표시 |
| 계산 불가 | 가격·레시피·초기재고 등 구체적인 부족 근거 표시. 잘못된 일부 기록을 조용히 빼고 전체 결과처럼 표시하지 않음 |
| 손실·음수 잔량 | 음수 그대로 표시. 0으로 바꾸지 않음 |
| 저장 전 입력 | 입력창 안에서만 미리보기. 취소하면 기록·집계·재고에 영향 없음 |
| 저장·삭제 완료 | 저장한 기록을 기준으로 관련 결과를 갱신. 조회·재조회·화면 이동만으로 자료를 바꾸지 않음 |
| 파일 결과 | 조회·입력 자체로 외부 파일을 만들지 않음. 백업과 복원 전 보존에서만 백업 파일 생성 |
| 마감 | 제공 달력의 영업·마감 상태를 사용. 새 기록이 있다고 자동 마감하지 않음. 달력이 없는 날짜는 마감 미확인 |

## 4. 기능별 상세 요구사항

### F01. 최초 자료 준비·확인

- 시작: 처음 프로그램을 열거나 저장된 기록을 다시 연다.
- 처리: 작업 기록이 있으면 그것을 우선 사용한다. 작업 기록이 없을 때 제공 자료의 한 형식으로 한 번만 준비한다. ID·연결 대상·단위·기간·숫자·기록 수를 검사한다.
- 화면: 매장명, 가상 샘플 표시, 자료 기간, 마지막 마감일, 금액·수량 기준과 5개 기능 메뉴를 표시한다.
- 저장: 최초 자료 전체와 출처·형식 버전을 저장한다. 앱을 다시 열거나 배포 코드가 갱신되어도 샘플을 기존 기록 위에 다시 넣지 않는다.
- 오류: 최초 자료를 읽지 못하면 원인과 재시도 안내를 표시한다. 기존 저장소를 읽지 못할 때 새 샘플로 덮지 않는다. 일부 연결 오류가 있으면 관련 계산을 미확인으로 둔다.

### F02. 화면 이동·기간 조회

- 공통 메뉴: 기간별 실적 및 손익, 판매 기록 관리, 메뉴별 수익성 분석, 비용 기록 관리, 재료 잔량 및 부족 현황으로 이동한다. 본점 표시는 매장 전환 기능이 아니다.
- 조작: 일간은 날짜 한 개, 월간은 연·월, 직접 지정은 시작일·종료일을 선택하여 조회한다. 일간·월간 버튼만 누르는 것으로 날짜를 임의 고정하지 않는다.
- 결과: 선택 기간은 5개 화면에서 공유한다. 재료 잔량은 기간 마지막 날짜 기준이고 나머지 실적·판매·비용은 기간 안의 기록이다.
- 표시: 선택 범위와 실제 기록 범위를 함께 표시한다. 달력상 마감일·미마감일·휴무일을 혼동하지 않는다. 미래 구간은 미마감으로 표시하며 예상 매출 점선은 만들지 않는다.
- 오류: 시작일이 종료일보다 늦거나 날짜가 비면 조회하지 않고 해당 칸을 안내한다. 유효한 기존 조회 결과는 유지한다.
- 예외: 데이터 시작 전의 재고는 미확인. 기록이 없는 기간은 기록 없음, 마감된 영업일의 확인된 무판매는 판매 0으로 구분한다. 일부 연간 자료는 해당 기록 범위만 보여준다.
- 파일: 조회 조건으로 외부 파일은 생성하지 않는다.

### F03. 판매 기록 조회

- 진입: 판매 메뉴 또는 전체 판매 기록 보기. 기간 실적의 최근 판매 미리보기는 선택 범위 안의 최근 기록 최대 5건이다.
- 조회: 선택 기간의 메뉴·매장/포장/전체로 좁혀 볼 수 있다. 이 조작은 판매 조회의 구체화이며 새 데이터 기능은 아니다.
- 결과: 판매ID, 일자, 등록 메뉴명, 채널, 수량, 당시 판매단가, 총 할인, 순매출, 총 결제수수료, 총 식재료·포장 원가, 확인 상태, 수정·삭제 작업을 표시한다. 레시피버전과 개당 원가는 수정창에서 확인한다.
- 합계: 목록과 요약은 같은 조회 조건을 따른다. 페이지를 나눠도 합계는 전체 조회 대상이고 화면에 보이는 한 페이지만의 합계가 아니다.
- 예외: 일치 기록이 없으면 빈 목록과 기록 없음 안내. 등록 메뉴를 찾지 못하는 기록은 ID와 연결 오류를 표시하며 누락시키지 않는다.
- 파일: 1차에는 판매 엑셀 내보내기를 하지 않는다.

### F04. 판매 추가·수정·삭제·취소

| 입력칸 | 저장할 내용과 검사 |
| --- | --- |
| 판매일자 | 필수, 유효한 날짜. 초기재고 기준일 전 판매는 추가하지 않음 |
| 메뉴 선택 | 등록된 8개 메뉴 중 하나. 임의 옵션·새 메뉴 없음 |
| 판매채널 | 매장 또는 포장, 필수 |
| 판매수량 | 필수, 양의 정수. 0건 판매를 별도 입력하지 않음 |
| 판매 당시 단가 | 원·부가세 제외, 0 이상의 금액. 신규는 메뉴 기준가 참고, 실제 금액 정정 가능 |
| 적용 총 할인액 | 해당 집계 기록 전체 할인, 0 이상. 수량×단가를 넘는 할인은 오류 |
| 개당 식재료 원가 | 기본값 또는 직접 정정. 미확인일 때 빈칸 저장 가능, 음수 불가 |
| 개당 포장 원가 | 적용 채널과 레시피 기준. 미확인일 때 빈칸 저장 가능, 음수 불가 |
| 총 결제수수료 | 기록 전체 금액. 기준이 없으면 직접 입력. 확인된 0 허용, 빈칸은 미확인, 음수 불가 |

- 추가: 신규 판매 기록 추가 또는 판매 기록 추가를 누르면 같은 입력 규칙의 창을 연다. 메뉴·채널·판매일 기준으로 원가 기본값을 준비하고 입력 변경에 따른 순매출·직접비·기여이익을 미리 보여준다.
- 저장: 필수 항목과 유효성을 검사한다. 원가·수수료만 미확인인 기록은 미확인 상태로 저장할 수 있다. 새 판매ID를 부여하고 저장 성공 후 목록·메뉴 수익성·기간 손익·관련 재료 잔량을 갱신한다.
- 중복: 같은 일자·메뉴·채널이 있으면 별도 신규 집계를 자동으로 추가하지 않는다. 기존 기록을 수정하도록 안내한다. 예를 들어 오전 10잔 기록 후 오후 5잔이 추가되면 기존 일 집계수량을 총 15잔으로 고친다.
- 수정: 기존 ID를 유지한다. 당시 원가·수수료를 불필요하게 최신값으로 바꾸지 않는다. 메뉴·채널·일자 등 원가 기준이 바뀌면 변경 이유와 새 기본값을 확인하게 하고, 이전 메뉴·기간·재료와 새 대상의 결과를 함께 갱신한다. 총 수수료는 근거 없이 비례 변경하지 않고 사용자가 확인한다.
- 삭제: 대상 날짜·메뉴·채널·수량을 확인한 후 삭제한다. 취소하면 유지. 성공 시 관련 집계에서 해당 기록을 제외한다. 다른 판매와 제공 재고·실측 기록은 삭제하지 않는다.
- 취소·닫기: 저장하지 않은 입력은 적용하지 않는다. 변경 내용이 있으면 버릴지 확인하여 실수로 닫는 것을 줄인다.
- 오류: 필수 누락·숫자 오류·중복·저장 실패는 입력을 유지하며 원인을 안내한다. 저장 버튼 연속 클릭으로 중복 생성하지 않는다. 실패한 기록을 재고에 반영하지 않는다.
- 재고 부족: 등록 재고가 부족하더라도 실제 판매 정정을 막지 않는다. 저장한 결과가 음수면 기록상 부족을 표시한다. 자동 발주하지 않는다.
- 파일: 판매 저장만으로 엑셀·백업 파일이 생성되지는 않는다.

### F05. 원가·수수료 기본값과 정정

- 신규 원가: 판매일보다 늦지 않은 가격이력 중 가장 최근 자료와 등록된 레시피버전을 사용한다. 구매가격은 구매용량 전체 가격이다. 채널 제한 없는 재료와 선택 채널에 맞는 재료만 적용한다.
- 포장: 제공 자료에서는 포장 판매에 포장세트가 쓰이고 매장에는 쓰이지 않는다. 구성품별 컵·슬리브·캐리어를 임의로 더하지 않는다. 음료와 디저트의 포장 재료를 구분한다.
- 수수료: 기존 판매는 기록된 총 수수료를 사용한다. 신규 판매는 확인된 기준이 없는 현재 자료에서 빈칸으로 시작하여 직접 보완한다. 시안의 3%나 샘플에서 역산한 비율을 계약 기준으로 적용하지 않는다.
- 정정: 직접 고친 원가·수수료를 보존한다. 수량이나 할인 변경만으로 직접 고친 값을 덮지 않는다. 기준 항목 변경 시 이전 값이 그대로 유효하다고 표시하지 않는다.
- 재료 사용량: 금액 원가를 고치는 것과 레시피 사용량을 고치는 것은 다르다. 금액 원가 정정만으로 재고 사용량이 바뀌지 않는다. 레시피 편집은 1차에 없다.
- 오류: 레시피·가격이력 누락, 구매용량 0, 단위 불일치, 중복 적용일 가격은 해당 기본값을 미확인으로 표시한다. 최신 미래 가격으로 대체하지 않는다. 레시피 연결을 모르면 재고 계산도 관련 범위에서 미확인이다.

### F06. 메뉴별 수익성 조회

- 입력: 공통 기간과 메뉴 분류 전체·음료·디저트, 채널 전체·매장·포장.
- 결과: 등록 메뉴별 판매수량·순매출·식재료 원가·포장 원가·수수료·기여이익·기여이익률·원가 확인 상태를 표시한다. 기여이익은 판매에서 직접 드는 비용을 제외하고 남는 금액이며 매장의 최종 이익과 다르다.
- 개당 요약은 실제 판매수량을 반영한 평균이다. 여러 당시 가격·원가가 섞이면 단일 최신 가격처럼 표현하지 않는다. 등록 기준가와 실제 평균 판매단가를 구분한다.
- 정렬: 시안의 기여이익·비율·판매량 정렬은 조회 조작으로 채택한다. 같은 값은 메뉴ID 순, 미확인은 뒤에 표시하되 누락시키지 않는다. 정렬은 우수·주의 등의 등급 판정이 아니다.
- 예외: 판매가 없는 메뉴는 판매 없음. 순매출 0의 비율은 계산 불가. 필요한 원가가 없는 메뉴는 금액 일부와 미확인 이유를 보이고 이익·비율은 확정하지 않는다.
- 파일: 원가 내역 엑셀 받기 없음. 사분면·전략 제언·민감도·매핑 설정 없음.

### F07. 비용 조회·추가·수정·삭제·취소

- 조회: 공통 기간의 귀속일별 비용을 표시한다. 검색은 기존 비용분류에 한정한다. 시안의 거래처 검색은 1차에서 제거한다. 분류 필터와 이전·다음 목록 이동은 조회 조작으로 사용하며 항목별 합계는 전체 조회 대상 기준이다.
- 목록: 비용ID·귀속일·8개 분류 중 해당 항목·금액·기존 배분기준·수정·삭제. 카드매입·증빙 검증·거래처 등 자료에 없는 내용은 표시하지 않는다.
- 필수 입력: 귀속일, 등록된 비용분류, 0 이상의 원 단위 금액. 신규 배분기준은 귀속일 직접 입력이다. 원본의 월비용 일할 배분 문구는 보존한다.
- 추가·수정: 검사 후 저장한다. 수정은 비용ID 유지. 월계획을 자동 변경하거나 월별 일자 기록을 추가 생성하지 않는다. 같은 날짜·분류에도 여러 비용이 있을 수 있으므로 해당 조합만으로 자동 합치지 않는다.
- 중복 확인: 동일 날짜·분류·금액의 신규 비용은 기존 기록을 보여주고 별도 비용인지 확인하도록 권고한다. 기존 비용 정정은 기존 기록을 수정한다. ID 중복은 허용하지 않는다.
- 삭제: 대상 확인 후 해당 비용만 삭제하고 기간 비용 합계·손익을 갱신한다. 월계획이나 같은 분류의 다른 날짜 기록을 삭제하지 않는다.
- 취소·닫기·오류: 판매 입력과 같은 취소·미저장 보호·저장 실패 처리. 빈 날짜·분류·금액 또는 음수·숫자 아닌 금액은 저장하지 않는다.
- 파일: 비용 저장으로 외부 파일 생성 없음. 임시저장·월 자동 배분·부가세 자동 분리·첨부 기능 없음.

### F08. 기간 실적·매장 손익 조회

- 입력: F02의 기간. 메뉴·채널 필터로 좁힌 메뉴 분석과 달리 매장 손익은 매장 전체 기록 기준이며 그 차이를 표시한다.
- 지표: 순매출, 판매 식재료·포장 원가, 결제수수료, 기여이익, 귀속일 운영비용, 폐기 손실 비용, 매장 손익. 폐기 처리 기준은 5절 C06을 따른다.
- 화면: 선택 범위의 일별 순매출·비용 흐름, 채널별 판매수량·순매출, 최근 판매, 현재 부족 재료를 기존 지표를 바탕으로 보여준다. 미래 예측선은 없음. 현재 부족 영역은 F09와 같은 기준이다.
- 평균·비율·최고일: 기간 내 마감된 실제 영업일을 기준으로 평균을 낸다. 미마감 기록이 섞이면 부분 실적임을 표시한다. 최고 매출일은 확인된 순매출 기준이고 동률이면 해당 날짜를 함께 표시한다.
- 예외: 순매출 0이면 이익률은 계산 불가. 운영비만 있는 날의 손실도 표시한다. 원가·수수료·폐기 평가가 미확인이면 최종 손익을 확정하지 않는다. 월계획은 운영비 합계에 더하지 않는다.
- 파일: 지표·차트 조회 자체로 보고서 파일을 만들지 않는다.

### F09. 재료 잔량·현재 부족·실측·변동 기록 조회

- 입력: 공통 기간 종료일. 상태 필터는 전체·잔량 있음·잔량 없음 또는 기록상 부족·미확인으로 정리한다. 안전재고 미달 필터는 사용하지 않는다.
- 잔량: 초기재고일부터 종료일까지 판매의 레시피 사용량과 입고·폐기·실사조정 증감을 반영한다. 조회 시작일이 달라도 종료일이 같으면 잔량은 같다.
- 결과: 11개 재료의 이름·단위·공급사·구매규격·최초가격, 초기재고·누적 입고·누적 판매 사용·누적 폐기·누적 실사조정·기록상 잔량·종료일 이전 최근 실측 날짜·수량·확인 상태를 표시한다.
- 부족: 잔량 0은 남은 재고 없음, 음수는 기록상 부족, 양수는 잔량 있음이다. 양수가 있다는 이유로 미래 판매에도 충분하다고 판정하지 않는다.
- 실사 내역 조회: 제공 실사조정의 날짜·재료·증감·실측수량·사유를 조회한다. 기간 이후 실측을 과거 잔량 근거로 쓰지 않는다. 기록에 없는 시각·담당자·검증완료 상태를 만들지 않는다.
- 전체 변동 원장 보기: 선택 기간·재료의 입고·폐기·실사조정을 날짜·기록ID 순으로 조회한다. 양수·음수와 단위를 보존한다. 새 기록 입력은 없음.
- 판매 정정: 변경 이후 관련 실사 날짜의 다시 계산한 잔량이 보존된 실측과 다르면 실사 재확인 필요를 표시한다. 실측수량이나 기존 조정값을 자동으로 다시 쓰지 않는다.
- 오류: 초기재고·레시피·단위가 불명확하면 관련 잔량은 미확인. 연결 없는 판매로 영향을 받을 재료를 알 수 없으면 전체 잔량 정확성을 보장하지 않으며 그 이유를 표시한다. 실측값이 없으면 실측 기록 없음이며 0으로 채우지 않는다.
- 파일: 조회로 재고 파일·발주서 생성 없음. 발주·배송·고갈시점 없음.

### F10. 저장·다시 열기

- 판매·비용의 저장·삭제와 최초 자료 준비·복원 완료 시 저장한다. 입력 중인 폼은 아직 저장된 기록이 아니다.
- 상태: 저장 중 → 실제 성공 시 저장됨. 실패 시 저장 실패와 미적용 내용을 표시한다. 저장 실패를 정상 가동·동기화 완료로 표현하지 않는다.
- 재시작: 마지막으로 성공한 전체 기록과 원가·수수료 정정값을 다시 읽고 동일 기준으로 결과를 계산한다.
- 오류: 저장 공간 부족·저장소 사용 제한·손상 시 기존 자료를 유지하고 재시도 또는 보유 백업 복원으로 안내한다. 새 샘플로 덮지 않는다. 아직 저장되지 않은 입력은 유지한다.
- 한 기기 사용은 저장된 자료가 다른 기기로 자동 전달된다는 뜻이 아니다. 브라우저 자료를 삭제하면 백업이 필요할 수 있다. 백업은 별도 파일이어야 한다.

### F11. 전체 자료 수동 백업

- 조작: 공통 백업 또는 데이터 로컬 백업 다운로드.
- 처리: 마지막으로 저장 완료된 자료의 일관된 전체 상태를 만든다. 저장 중이면 완료를 기다리며, 실패 상태에서 아직 미저장된 내용을 백업했다고 안내하지 않는다.
- 파일: 앱 전용 JSON. 판매·비용·초기재고·재고기록·메뉴·재료·공급사·레시피·가격·달력·월계획·자료정보·계산 기준 버전·자료 형식 버전·백업 생성시각·자료 건수를 포함한다. 빈칸·부호·정정값을 보존한다.
- 이름 예: `prep-cafe-backup-20261012-153000.json`. 시간은 생성시각이며 원자료 마감일과 구분한다.
- 결과: 파일 생성과 다운로드 시작을 안내한다. 사용자가 실제 저장 위치에 파일을 보관했는지는 프로그램이 확정했다고 표시하지 않는다.
- 오류: 생성·다운로드 실패 때 현재 기록을 바꾸지 않고 다시 시도하게 한다. 재료 잔량 11개만 담은 시안의 예시 파일은 정상 전체 백업으로 인정하지 않는다.

### F12. 전체 자료 복원

1. 복원 버튼을 눌러 파일 선택창을 연다. 프로그램이 만든 전체 JSON 백업 한 개를 선택한다.
2. 형식·버전·매장 식별·기간·ID 중복·연결 관계·숫자·단위·필수 기록 묶음을 검사한다. 미확인 금액은 정상 허용 상태로 검사하며 0으로 바꾸지 않는다.
3. 검사에 통과한 백업의 생성시각·기록기간·자료 건수와 전체 교체 의미를 보여준다. 파일명·확장자만으로 성공을 판단하지 않는다.
4. 현재 저장 기록 전체를 복원 전 백업 파일로 먼저 보존할 수 있게 한다. 보존 파일 생성이 실패하면 복원을 진행하지 않는다.
5. 운영자가 복원 실행을 확인하면 백업의 전체 상태로 교체한다. 기존 기록과 합치지 않는다. 복원 성공 후 결과를 다시 계산하고 저장됨을 표시한다.

- 취소: 검사·선택·확인 중 취소하면 현재 자료 유지. 복원 실행 중에는 추가 저장·삭제를 받지 않는다.
- 실패: 손상·지원하지 않는 버전·다른 매장·누락 묶음·ID 충돌·저장 공간 부족은 오류 이유를 표시하고 전체 교체하지 않는다. 교체는 전부 성공하거나 기존 상태를 유지해야 한다.
- 원본 샘플 JSON·시안의 재료 일부 JSON·엑셀은 앱 백업과 다르므로 1차 복원 대상으로 받아들이지 않는다.
- 결과 파일: 복원 전 전체 백업 파일. 복원 자체는 사용자가 선택한 파일을 수정하지 않는다.
- 시안의 무조건 성공 알림·검사하지 않은 CRC32 OK·고정 검증시각은 사용하지 않는다.

## 5. 채택한 계산 기준

아래는 자료에 들어 있던 정책을 발견한 것이 아니라 이번 FRD에서 제안한 추천 계산을 채택한 것이다. 기존 판매의 확정 순매출·수수료·개당 원가는 원본 그대로 보존한다. 새 기록·명시적으로 정정한 값과 집계에 아래 기준을 사용한다.

| 번호 | 계산 방법 | 예외 |
| --- | --- | --- |
| C01 순매출 | 판매수량×당시 판매단가−해당 기록 총 할인액 | 할인 초과는 저장 오류. 전액 할인으로 0은 허용. 음수로 자동 보정하지 않음 |
| C02 개당 원가 기본값 | 판매일에 유효한 재료 구매가격÷구매용량×레시피 개당 사용량을 재료별로 합산. 식재료와 포장재는 별도 합계 | 유효 가격·레시피·단위가 없으면 미확인. 매장 판매의 해당 없음 포장 원가는 확인된 0 |
| C03 기록별 직접비 | 총 식재료 원가=수량×개당 식재료 원가. 총 포장 원가=수량×개당 포장 원가. 직접비=두 원가+총 결제수수료 | 원가·수수료 누락 시 직접비·이익 미확인. 수수료는 개당 금액으로 다시 곱하지 않음 |
| C04 메뉴 수익성 | 기여이익=순매출−직접비. 기여이익률=기여이익÷순매출×100 | 음수 이익 유지. 순매출 0의 비율은 계산 불가 |
| C05 기간 집계 | 조건에 맞는 기록별 금액·수량 합계. 전체 이익률은 전체 기여이익÷전체 순매출. 개당 평균 금액은 해당 총액÷판매수량 | 메뉴별 비율을 단순 평균하지 않음. 수량 0의 개당 평균은 계산 불가. 미확인 일부를 빼고 완전 합계로 표현하지 않음 |
| C06 매장 손익·폐기 | 매장 손익=기간 기여이익−귀속일 비용 합계−폐기 손실 비용. 폐기 비용=폐기수량의 절댓값×폐기일 유효 재료 단위가격 | 폐기 금액은 제공 기록에 없으므로 가격이력 기준 추정임을 표시. 구매 입고 전체를 다시 판매원가에 더하지 않음. 실사조정은 1차 손익에서 별도 금액화하지 않고 포함하지 않은 항목임을 안내. 판매·폐기 원가를 비용기록에도 다시 입력해 중복시키지 않음 |
| C07 재료 사용량 | 해당 판매수량×해당 레시피버전의 재료 사용량. 채널 제한 재료는 그 채널에서만 사용 | 금액 원가 직접 정정은 레시피 사용량을 바꾸지 않음 |
| C08 재료 잔량 | 초기수량+종료일까지 재고기록의 증감수량 합계−종료일까지 판매 사용량 합계 | 재고기록에 폐기·실사조정의 부호가 이미 있으므로 다시 반대로 적용하지 않음. 실측수량을 별도 입고처럼 추가하지 않음 |
| C09 실측 대조 | 실사 날짜를 하루 마감 기준으로 보고 그 날짜까지 다시 계산한 잔량과 보존된 실측수량 대조 | 자료에 시간 순서가 없으므로 장중 순서를 추정하지 않음. 차이가 있으면 재확인, 실측 자동 변경 없음 |
| C10 부족 상태 | 잔량 0=없음, 음수=기록상 부족, 양수=잔량 있음 | 양수에서 안전재고 미달·미래 충분 여부는 판정하지 않음 |
| C11 흐름·채널·평균 | 일별 합계는 같은 귀속일·판매일로 묶음. 채널 비중=해당 채널 판매수량÷전체 판매수량. 일평균은 마감 영업일 합계÷해당 영업일 수 | 비영업일·미마감일은 영업일 평균의 분모에 넣지 않음. 분모 0이면 계산 불가. 미마감 입력을 마감 평균에 섞지 않음 |
| C12 반올림 | 개당 원가와 원자료 소수는 계산 중 보존. 기록별 식재료 총원가·포장 총원가·폐기 비용을 각각 원 단위 반올림한 뒤 합산. 0.5원은 올림. 비율은 최종 표시만 소수 첫째 자리 | 화면별로 다른 반올림을 사용하지 않음. 원본 소수 원가를 저장할 때 먼저 버리지 않음 |

기존 기록의 순매출이 C01과 맞지 않는 경우 원본을 자동 수정하지 않는다. 차이를 표시하여 해당 기록 정정이 필요함을 알린다. 제시한 매장 손익은 프로그램에 포함된 비용의 결과이며 자료에 없는 비용까지 반영한 공식 회계 결산이라고 표현하지 않는다.

### 계산 설명용 예

2026-09-18 카페라떼 포장 12잔, 판매단가 4,800원, 총 할인 2,000원, 개당 식재료 1,123.2원·포장 172.8원, 사용자가 확인하여 입력한 총 수수료 800원이라는 설명용 기록을 가정한다. 800원은 실제 계약 수수료가 아니라 예시 입력값이다.

- 순매출: 12×4,800−2,000 = 55,600원.
- 총 식재료: 12×1,123.2 = 13,478.4원 → 13,478원. 총 포장: 12×172.8 = 2,073.6원 → 2,074원.
- 직접비: 13,478+2,074+800 = 16,352원. 기여이익: 55,600−16,352 = 39,248원. 기여이익률: 70.6%.
- 레시피에 따른 판매 사용량: 원두 240g, 우유 2,400ml, 포장컵세트 12개. 기존 12잔을 10잔으로 정정하면 10잔 기준으로 다시 계산하며, 12잔 사용량과 10잔 사용량을 둘 다 차감하지 않는다.
- 원가·수수료 중 하나가 빈칸이면 55,600원 순매출과 판매수량은 알 수 있지만 기여이익은 미확인이다.

## 6. 2차 확장 범위와 계산 제안

아래는 PRD에 있는 확장의 검토 방법이며 1차 동작이 아니다. 참고 기간 같은 세부 숫자는 아직 확정하지 않는다. 신규 발주·배송·회원가입 기능은 추가하지 않는다.

| 확장 | 사용 흐름·계산 제안 | 주요 오류·예외와 결과 |
| --- | --- | --- |
| 엑셀 양식·가져오기 E01 | 지정 판매·비용 양식 내려받기 → 작성 파일 선택 → 날짜·ID·연결·단위·중복 검사 → 추가 대상 확인 → 저장 | 시트·열 이름 오류, 식·날짜·숫자 오류와 중복 행을 안내하고 자동 덮어쓰기하지 않음. 부분 반영 여부·행 식별 규칙은 2차 FRD에서 확정 |
| 입고·폐기·실제 재고 E02 | 재료·날짜·유형·수량·사유 기록과 실측 조회. 부호와 마감 기준 보존 | 실측과 과거 판매 정정 충돌 처리·입력 부호 방식은 2차 상세 설계. 재고 변동 후 해당 재료 잔량 갱신 |
| 주·분기·반기·연간 E03 | 확정한 달력 기준으로 기간을 바로 선택. 금액 합계는 C05와 같음 | 연간 일부 기간·미마감 포함 여부 표시. 비교 기능은 별도 상세 정의 |
| 월말 예상 손익 E04 | 마감된 영업일의 평균 판매수량·채널 비중을 남은 예정 영업일에 적용하고, 확인된 가격·원가·수수료와 월비용계획을 참고하여 실제+잔여 예상 구분 | 마감 실적이나 미래 달력·가격·수수료·계획이 없으면 예상 불가. 날씨나 행사 효과를 임의로 넣지 않음. 평균 참고 기간·비용 반영 방법은 미정 |
| 필요 발주량 E05 | 최근 마감 영업일의 일평균 재료 사용량×납기·안전재고 영업일을 참고한 목표량과 잔량 차이 → 구매용량으로 묶음 수 올림 참고 | 사용 실적·납기·구매용량이 없거나 0이면 발주 참고 불가. 이미 주문한 양·유통기한 등 없는 자료를 추정하지 않음. 참고 기간·정확한 목표량은 미정. 주문 전송 없음 |
| 수익성 분석 E06·기초자료 E07 | 필요 확인 후 등급·가격·레시피 편집 범위를 별도 결정 | 과거 기록 보존. 시안의 65% 등급·사분면·자동 제언은 확정 기능이 아님 |

시안에만 있는 보고서 엑셀 내보내기, 자동 월 비용 배분, 임시저장, 거래처·증빙 입력, 부가세 처리, 발주·배송, 민감도 분석은 별도 확장 후보이며 PRD의 2차 필수 기능으로도 자동 추가하지 않는다.

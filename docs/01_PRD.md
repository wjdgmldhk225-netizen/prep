# 카페 판매·수익·재고 관리 제품 요구사항 문서(PRD)

- 작성일: 2026-10-12
- 상태: 1차 제품 범위 확정. 사용자의 “모두 추천으로 해줘”에 따라 남은 제품 선택은 추천안을 채택했다. 계산·설계·기술·상세 동작은 후속 단계에 남긴다.
- PRD란: 누구의 어떤 문제를 해결하고, 어떤 기능까지 만들지 정리하는 문서다.
- MVP란: 가장 중요한 일을 처음부터 끝까지 해볼 수 있는 첫 버전이다.
- 이번 문서의 범위: 목적, 자료의 의미, 핵심 사용 흐름, 단계별 기능 제안, 완료 기준, 미정 사항.
- 계산식, 화면 디자인, 기술 선택, 상세 동작, 코드는 이 문서에서 정하지 않는다.

## 1. 제품 목적과 사용자

카페 운영자가 판매 기록을 입력한 뒤 메뉴별 수익성을 확인하고, 같은 기간의 매장 손익과 재료 잔량을 이어서 확인하는 웹 프로그램을 만든다. 1차의 메뉴 수익성은 판매에 직접 드는 식재료·포장재·결제수수료를 고려해 메뉴 판매가 매장에 얼마나 도움이 되는지 확인한다. 임차료·인건비 등 운영 비용은 메뉴마다 나누지 않고 매장 전체 손익에서 확인한다. 구체적인 계산식과 수익성 분류 기준은 이번 결정에 포함하지 않는다.

사용자는 카페 운영자다. 첫 버전은 한 매장·한 운영자·지정한 한 기기에서 사용한다. 여러 매장·여러 직원·여러 기기의 공동 사용은 1차에서 제외한다. 사용 환경의 구체적인 기술은 후속 단계에서 정한다.

첫 버전의 성공은 운영자가 기록을 고친 후 관련 결과를 확인하고, 저장한 기록을 다시 열거나 백업에서 되돌릴 수 있는 것으로 판단한다. 메뉴 중단이나 자동 발주는 1차에 포함하지 않는다.

## 2. 자료에서 확인한 사실

### 2.1 검토한 자료와 범위

검토 자료는 작업 폴더의 `데이터설명.md`, `매장운영데이터.xlsx`, `매장운영데이터.json`이다.

- 직접 구성한 가상 매장 샘플이며 매장명은 프렙 카페다. 실제 거래 내역이 아니다.
- 실적 기록은 2025-07-01부터 2026-09-18 마감까지다.
- 영업달력은 2026-09-30까지 있다. 마지막 12일은 미마감 상태다.
- 금액은 원이며 부가세 제외 기준이다. 재료 수량 단위는 g·ml·개다.
- 엑셀과 JSON은 같은 기록의 두 형식이다. 주요 11개 기록 묶음의 전체 행을 비교했으며, 날짜 표현과 빈칸 표현 차이를 맞추면 값이 일치한다. 자료정보도 JSON의 출처·기간 정보와 일치한다.
- 판매ID·재고기록ID·비용ID의 중복은 발견하지 않았다. 일자·메뉴·판매채널 조합의 판매 기록 중복도 발견하지 않았다. 이는 검토한 샘플의 상태이며, 앞으로 가져올 파일의 품질까지 보장하지 않는다.
- JSON의 `settings`는 비어 있다. 수익성 분류, 예상 손익, 발주 판단 등 운영 정책이 정해져 있다는 근거는 없다.

### 2.3 기획할 때 주의할 점

| 확인한 사실 | 기획에 반영할 주의점 |
| --- | --- |
| 판매는 일자·메뉴·채널별 집계다. | 판매수량을 주문 건수나 고객 수로 표현하지 않는다. |
| 엑셀과 JSON은 같은 자료다. | 두 형식을 따로 더하면 판매·재고·비용이 중복될 수 있다. |
| 월비용계획과 비용기록은 같은 비용의 월·일 표현이다. | 서로 독립적인 지출로 합산하지 않는다. 비용기록의 날짜는 귀속일이며 실제 결제일로 단정하지 않는다. |
| 구매가격은 구매용량 전체의 금액이다. | 예를 들어 원두 1,000g의 가격을 1g 가격으로 해석하면 안 된다. |
| 레시피는 메뉴 한 개 기준이며 일부 포장재는 포장 채널 전용이다. | 매장 판매에도 포장재를 일괄 적용하지 않는다. |
| 판매에 당시 단가·원가·수수료가 기록되어 있다. | 최신 가격으로 과거 기록을 임의로 바꾸지 않는다. 새 기록과 과거 수정의 제품 기준은 9절의 결정으로 구분하고, 계산 방법은 후속 단계에서 정한다. |
| 입고는 양수, 폐기는 음수, 실사조정은 양수·음수 모두다. | 재고기록의 부호를 보존한다. 실측수량과 증감수량을 동일한 의미로 취급하지 않는다. |
| 미마감 날짜와 빈칸이 있다. | 미입력을 매출 0이나 재고 0으로 단정하지 않는다. 휴무일과 기록 누락도 구분한다. |
| 납기·안전재고 일수는 영업일 기준이다. | 휴무를 포함한 일반 날짜 수로 해석하지 않는다. |
| 연간 자료는 일부 기간만 포함한다. | 일부 기간 실적을 온전한 한 해 실적으로 표시하지 않는다. |
| 기존 원가·수수료·배분 결과는 과거 기록이다. | 그 값이 있다는 이유로 앞으로의 비용 배분이나 전망 정책이 합의되었다고 보지 않는다. |

## 3. 요청된 전체 기능과 단계별 범위

아래 1차 범위는 4시간 제한을 고려한 추천안으로 확정했다. 사용자가 먼저 선택한 직접 입력 중심 범위와 메뉴 수익성 기준을 유지한다. 2차는 확장 방향으로 채택하며, 별도 일정에서 구현한다.

| 사용자 요청 | 1차 구현 범위 | 2차 확장 방향 |
| --- | --- | --- |
| 판매 기록 입력·수정·삭제 | 포함 | 입력 편의 개선 |
| 비용 기록 입력·수정·삭제 | 포함 | 월비용계획 작성·수정과 반복 비용 관리 |
| 메뉴별 수익성 | 식재료·포장재·결제수수료를 고려한 기본 결과 확인. 임차료·인건비 등은 매장 전체 손익에서 확인. 좋음·주의 등의 등급 분류는 제외 | 여러 기준 비교, 필요에 따른 수익성 분류와 분석 확대 |
| 기간별 실적·손익 | 일·월·직접 지정한 날짜 범위 조회 | 주·분기·반기·연간의 바로 조회와 기간 비교 |
| 예상 손익 | 제외 | 실제 실적과 구분되는 예상 손익 |
| 재료 잔량·부족 확인 | 기존 초기재고·판매·재고기록을 바탕으로 선택 기간 마지막 날짜의 잔량 확인. 남은 재고가 없거나 기록상 모자란 재료를 구분 | 앞으로의 부족 예상과 필요한 발주량 참고 |
| 입고·폐기·실제 재고 기록 | 제공 자료 조회만 포함 | 직접 입력·수정·삭제 및 실제로 센 수량 기록 |
| 엑셀 양식 내려받기·기록 가져오기 | 제외. 제공 샘플은 처음 사용할 자료로 준비 | 판매·비용 기록용 지정 엑셀 양식과 가져오기. 재고 양식은 후속 확장 후보 |
| 저장·백업·복원 | 현재 작업 기록 저장, 수동 백업·복원 포함 | 자동 백업, 다른 기기와의 공동 사용 등은 필요 확인 후 검토 |

1차의 날짜 범위 조회로 주·분기·반기·연간에 해당하는 날짜를 지정할 수 있다. 해당 기간을 바로 선택하는 기능과 별도의 비교 기능은 2차로 둔다. 기간은 달력 기준이며 주는 월요일 시작, 반기는 1~6월·7~12월, 연간은 1~12월로 정한다. 구체적인 기간 선택 동작은 설계 단계에서 정한다.

제공 샘플을 처음 사용할 자료로 준비하는 것과 사용자가 새 엑셀 파일을 반복해서 가져오는 기능은 범위가 다르다. 1차에는 임의 엑셀·JSON 파일을 가져오는 기능을 약속하지 않는다. 백업·복원도 일반 자료 가져오기와는 별도 요구다. 파일 형식은 아직 정하지 않는다.

## 4. 1차 핵심 사용 흐름

1. 운영자가 제공된 메뉴·재료·판매·비용·재고 자료를 확인한다.
2. 날짜·메뉴·판매채널별 판매를 입력하거나 기존 판매를 수정·삭제한다.
3. 해당 판매가 반영된 메뉴별 수익성을 확인한다.
4. 같은 기간의 판매 실적과 매장 손익을 확인하고 필요한 비용 기록을 입력·수정·삭제한다.
5. 선택 기간 마지막 날짜 기준으로 어떤 재료가 얼마나 남아 있는지, 남은 재고가 없거나 기록상 모자란 재료는 무엇인지 확인한다. 실제로 센 수량은 측정 날짜가 있는 별도 기록으로 확인한다.
6. 기록을 저장하고, 필요할 때 수동 백업과 복원을 사용할 수 있다.

예: 카페라떼 포장 판매 기록을 고친 후, 라떼의 수익성, 선택 기간의 매장 손익, 원두·우유·포장재 잔량을 이어서 확인한다. 이 예시는 사용 목적을 설명하며 계산 방법을 정하는 것은 아니다.

## 5. 1차 제품 요구사항

아래 요구사항은 확정한 1차 범위의 결과를 정의한다. 구체적인 계산과 구현 방법은 별도 단계에서 정한다.

| 번호 | 요구사항 | 완료 판단 기준 |
| --- | --- | --- |
| P01 | 제공 자료를 기반으로 시작한다. | 같은 샘플이 두 번 포함되지 않고 메뉴 8개·재료 11개 및 기록 묶음이 연결된다. |
| P02 | 판매 기록을 직접 입력·수정·삭제한다. | 운영자가 변경한 기록을 다시 확인하고, 그 변경이 관련 메뉴 결과·기간 실적·재료 잔량에 일관되게 반영된다. 새 판매의 원가·수수료는 확인된 기준으로 기본값을 준비한다. 근거가 없는 금액은 직접 보완하며 미입력을 0으로 처리하지 않는다. |
| P03 | 비용 기록을 직접 입력·수정·삭제한다. | 귀속일 기준 날짜별 비용을 관리한다. 변경한 비용을 다시 확인하고 관련 기간 손익에서 그 영향을 확인한다. 월비용계획과 중복으로 집계하지 않는다. 기존 배분 비용의 정정은 해당 기록을 수정하여 같은 비용이 추가 지출처럼 중복되지 않도록 한다. |
| P04 | 메뉴별 수익성을 확인한다. | 식재료·포장재·결제수수료를 고려한 메뉴별 결과와 관련 판매 실적을 확인한다. 임차료·인건비 등 운영 비용은 매장 전체 손익에서 확인한다. 1차에는 수익성 등급 분류를 제공하지 않는다. 필요한 원가·수수료가 없는 결과는 미확인 상태로 구분한다. |
| P05 | 일·월·날짜 범위별 실적과 손익을 확인한다. | 선택한 기간과 실제 기록 범위를 인지할 수 있고, 미마감·자료 없는 기간을 완료된 0원 실적으로 오해하지 않는다. |
| P06 | 재료별 잔량과 현재 부족 상태를 확인한다. | 선택 기간 마지막 날짜 기준의 재료명·수량·기준단위를 확인하고, 남은 재고가 없거나 기록상 모자란 재료를 구분한다. 실제로 센 수량은 측정 당시의 기록으로 보존한다. 과거 판매를 정정한 결과가 실측 기록과 충돌하면 재확인이 필요함을 인지할 수 있다. 기록으로 추정한 잔량을 실측값으로 표현하지 않는다. |
| P07 | 기록을 저장한다. | 지정한 한 기기에서 사용을 종료했다가 다시 시작해도 저장한 판매·비용 기록과 그 결과를 확인한다. 저장 수단은 기술 단계에서 정한다. |
| P08 | 수동 백업·복원한다. | 제공 기초자료와 사용자가 바꾼 기록 등 핵심 흐름 재현에 필요한 자료를 백업하고 복원한다. 복원은 기존 자료와 섞지 않고 백업 시점의 전체 기록 상태로 되돌리는 방식이다. 복원 전 작업 자료도 보존할 수 있어야 한다. 파일 형식과 상세 동작은 후속 단계에서 정한다. |
| P09 | 자료의 의미와 오류를 보존한다. | 빈칸과 실제 0, 과거 확정값과 미정 정책을 구분한다. 연결할 수 없는 메뉴·재료나 손상된 자료 때문에 잘못된 결과를 정상 결과처럼 보여주지 않는다. |

기초자료인 메뉴·레시피·재료·가격이력·공급사와 월비용계획의 직접 편집, 영업달력 편집, 새 메뉴 등록은 1차에서 제외한다. 1차는 제공 자료와 판매·비용 변경을 통해 핵심 흐름을 검증하는 버전이다. 새 입고·폐기·실제 재고를 계속 기록하는 일상 재고 운영은 2차 기능이 필요하다.

2차도 한 번에 전부 구현하는 약속은 아니다. 첫 버전 사용 후 우선순위를 정한다.

| E03 | 주·분기·반기·연간 바로 조회와 비교 | 원하는 기간의 실적을 쉽게 비교한다. | 월요일 시작 주와 달력 기준 기간을 사용한다. 일부 기록 기간과 미마감 기간을 구분하며 비교의 상세 구성은 설계 단계에서 정한다. |

| E05 | 부족 재료와 필요 발주량 참고 | 어떤 재료를 얼마나 준비할지 판단을 돕는다. | 최근 마감된 영업일의 사용 자료, 납기·안전재고 영업일, 구매 묶음을 참고한다. 수요 참고 기간과 발주량 산정 방법은 후속 계산 단계에서 정한다. |
| E06 | 메뉴 수익성 분석 확대 | 메뉴별 차이를 더 자세히 비교한다. | 등급이나 매장 비용의 메뉴별 배분은 확장 후보다. 도입 여부와 분류 기준은 2차 기획에서 정한다. |
| E07 | 기초자료와 계획 관리 | 메뉴·레시피·가격·영업일·월비용계획의 변화를 관리한다. | 변경해도 과거 실적 기준을 보존하는 방향이다. 편집 범위와 변경 이력의 상세 동작은 2차 기획에서 정한다. |

회원 가입, 권한 구분, 여러 매장, 결제 시스템 연동, 자동 발주, 날씨 기반 예측, 자동 백업은 1차에서 제외한다. 향후 필요할 경우 별도로 범위를 정한다.

## 7. 4시간 내 1차 구현 계획

시간 제한은 기획·화면 설계·개발·검사·배포를 합쳐 240분이다. 아래는 범위를 판단하기 위한 시간 배분이며 완료 보장이 아니다. 이 PRD 협의와 자료 확인도 기획 시간에 포함한다.

| 단계 | 제안 시간 | 완료 목표 |
| --- | ---: | --- |
| 기획 | 25분 | 자료 검토, 범위 확정, 이번 문서 밖의 계산 기준과 부족한 입력 근거 정리 |
| 화면 설계 | 25분 | 판매 기록부터 결과 확인까지 연결되는 최소 구성 확정. 설계 내용은 별도 문서에서 결정 |
| 개발 | 125분 | P01~P09의 핵심 흐름 구현 |
| 검사 | 45분 | 기록 변경, 결과 연결, 저장·복원을 대표 사례로 확인 |
| 배포 | 20분 | 합의한 이용 환경에서 프로그램을 열고 핵심 흐름 확인 |
| 합계 | 240분 | 사용할 수 있는 첫 버전 |

4시간 범위는 한 매장·한 운영자·한 기기, 제공 자료로 시작, 기초자료 조회 중심, 판매에 직접 드는 비용 기준의 메뉴 수익성, 실제 기록 중심의 손익·잔량 확인이다. 예상 손익·발주·범용 파일 가져오기와 공동 사용을 동시에 넣으면 4시간 계획을 다시 잡아야 한다.

1차 배포의 완료 기준은 운영자의 지정 기기에서 비공개로 프로그램을 열고 핵심 흐름을 사용할 수 있는 것이다. 공개 인터넷 서비스와 여러 기기 동기화는 포함하지 않는다. 구체적인 배포 기술과 계산 방법은 이 PRD의 결정 범위 밖이며 다음 단계에서 정한다. 실제 수수료 등 자료로 확인할 수 없는 값 때문에 결과가 미확인일 경우 그 한계를 표시한다. 시간이 부족할 때 기능을 임의로 생략하지 않고, 핵심 흐름을 유지하는 범위 조정을 먼저 합의한다.

## 8. 1차 검사에서 확인할 사용자 결과

- 판매를 추가·수정·삭제했을 때 해당 메뉴의 결과, 기간 실적·손익, 관련 재료 잔량이 합의한 기준에 맞게 연결된다.
- 매장과 포장 판매를 구분하며, 포장에만 쓰는 재료를 올바른 판매에 연결한다.
- 비용 변경이 해당 기간에 반영되고 월·일 비용을 이중으로 포함하지 않는다.
- 과거 원가·가격 기록을 보존하며, 수정한 과거 판매의 취급은 합의한 기준을 따른다.
- 재고기록의 입고·폐기·실사조정과 단위를 구분하고, 기록상 잔량과 실제로 센 수량을 혼동하지 않는다.
- 남은 재고가 없거나 기록상 모자란 상태를 확인한다. 충분히 남은 재료가 앞으로 며칠 뒤 부족해질지에 대한 전망은 1차 검사 대상이 아니다.
- 과거 판매 정정 뒤에도 당시 실측 기록을 사실처럼 바꾸지 않고, 필요한 재확인 상태를 인지할 수 있다.
- 자료 마지막 마감일 이후와 기록이 없는 기간을 완료된 실적으로 표현하지 않는다. 일부 연간 기록의 범위를 확인할 수 있다.
- 새 기록이 있다는 이유만으로 해당 날짜를 자동 마감으로 확정하지 않는다. 원가·수수료가 미입력인 결과를 확인된 수익으로 표시하지 않는다.
- 종료 후 다시 열기와 백업·복원 이후에도 바뀐 기록과 관련 결과를 확인한다.
- 잘못 연결된 자료나 사용할 수 없는 백업 때문에 정상처럼 보이는 잘못된 결과가 나오지 않는다.

검사에 쓸 숫자와 기대 결과는 계산 기준을 별도로 합의한 다음 작성한다. 이번 문서는 계산식이나 검사 코드를 정하지 않는다.

### 9.1 이번 문서에서 결정하지 않는 내용

다음 항목은 추천안 적용 후에도 남는다. 사용자가 제외한 문서 범위이거나 자료에 없는 실제 값이므로 임의로 확정하지 않는다. 추가 제품 선택 질문은 현재 없다.

| 구분 | 남겨둔 내용 | 후속 단계에서 필요한 일 |
| --- | --- | --- |
| 계산식 | 메뉴 수익성, 기간 손익, 폐기의 손익 반영, 재고 잔량·실사조정, 전망·발주량 산정 | 이번에 정한 비용 범위와 기록 보존 원칙을 바탕으로 계산 기준을 별도 문서에 정리한다. |
| 실제 운영 값 | 새 판매에 적용할 실제 수수료 기준, 제공 자료에 없는 새 가격·레시피 | 확인된 값을 사용한다. 확인 전에는 관련 금액을 직접 보완하거나 결과를 미확인으로 구분한다. 샘플의 금액을 실제 매장의 계약 조건으로 단정하지 않는다. |

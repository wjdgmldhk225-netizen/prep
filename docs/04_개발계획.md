# 1차 개발 계획

- 작성일: 2026-10-12
- 기준: PRD·FRD·TRD와 design 시안. 앞서 제안한 계획을 이번 “다음 EPIC 하나 구현” 요청의 기준으로 저장했다.
- 총 3개 EPIC·13개 Story(5+5+3). EPIC 1부터 순서대로 진행한다.
- 완료 표시 조건: 실제 구현·자동 검사·화면 검사 후 사용자가 문제없이 확인했다고 답한 EPIC만 완료로 표시한다.

| 순서 | EPIC | Story 수 | 상태 | 실제 화면에서 확인할 결과 |
| --- | --- | ---: | --- | --- |
| 1 | 판매 기록과 메뉴 수익성 | 5 | 구현·자동 검사·개발자 화면 검사 통과 / U01 확인·나머지 검수 보류 / 데모 진행 | 판매 추가·수정·삭제 후 메뉴 수익성 확인, 다시 열어도 기록 유지 |
| 2 | 비용과 매장 손익·재료 잔량 | 5 | 미착수 | 비용 관리 후 손익과 재료 잔량·실측 근거 확인 |
| 3 | 전체 기록 보호와 비공개 배포 | 3 | 미착수 | 전체 백업·복원과 보호된 Vercel 주소에서 사용 |

제공 자료·저장·판매 계산을 먼저 만든다. 비용과 재료 근거를 그 기록에 연결한 다음 기간 손익에 모으고, 전체 구조가 완성된 뒤 백업·복원·배포를 구현한다. 판매·비용의 추가·수정·삭제는 서로 다른 사용자 목적이므로 각각 나눴다. 재료 계산은 판매 변경의 영향 검증에 필요하므로 공통 계산으로 먼저 작성하지만 재료 조회 화면을 먼저 완성한 것으로 표시하지 않는다.

모든 Story는 실제 저장, FRD 계산 정확성, 입력·저장 오류와 취소 보호를 포함한다. 자동 검사를 통과해도 사용자 확인을 대신하지 않는다. 각 EPIC이 끝날 때 가상 자료로 실제 화면을 확인하며 실제 운영은 EPIC 3 이후 시작한다.

## EPIC 1. 판매 기록과 메뉴 수익성

의존성: 1.1 → 1.2 → 1.3·1.4 → 1.5. 원가 기본값·저장·공통 계산은 해당 Story의 구현 작업에 포함한다.

| Story | 사용자 목적 | 자동 검사 | 사용자 화면 확인·예상 결과 |
| --- | --- | --- | --- |
| 1.1 | 원하는 기간의 판매 기록 확인 | 최초 자료 중복 방지, ID·단위·날짜·조회 경계, 전체 합계, 기존 자료 보호 | 최초 6,112건. 다시 열어도 중복 없음. 미마감은 0원 확정으로 표시하지 않음 |
| 1.2 | 새 판매 집계 추가 | 가격·레시피·채널·반올림, 필수 입력·할인·중복·연속 저장, 저장 실패·취소 | 9/19 라떼 포장 12잔·단가 4,800·할인 2,000·수수료 800 입력 시 순매출 55,600원. 빈 수수료는 미확인 |
| 1.3 | 잘못된 판매 정정 | ID·당시 원가·직접 정정값 유지, 이전/새 집계·사용량, 변경 충돌 | 12잔→10잔·할인 유지 시 순매출 46,000원. 수수료 800을 임의 변경하지 않음 |
| 1.4 | 잘못 추가한 판매 삭제 | 해당 기록만 삭제, 집계·사용량 제외, 실측 유지, 취소·실패 | 취소하면 유지, 실행하면 해당 기록만 제거. 다시 열어도 삭제 유지 |
| 1.5 | 메뉴별 수익성 확인 | 금액 기준 이익률·평균·정렬, 0·손실·원가 누락 | FRD 예시의 직접 입력 원가 적용 시 기여이익 39,248원·70.6%. 미입력은 미확인, 등급 없음 |

예시 구분: 제공 가격이력으로 계산하는 라떼 포장 기본 원가는 개당 **166.4원**이다. FRD의 **172.8원**은 설명용 입력값이다. 39,248원 예시를 검수할 때 개당 포장 원가를 172.8원으로 직접 정정한다. 기본값과 설명용 입력을 구분하며 계산식은 변경하지 않는다.

완료 기준: 실제 판매 추가·정정·삭제와 메뉴 분석이 연결되고 저장·다시 열기·오류 검사를 통과한다. 사용자가 모든 검수 항목에 문제없음을 확인한 뒤 완료 표시한다.

## EPIC 2. 비용과 매장 손익·재료 잔량

의존성: EPIC 1 → 비용 관리와 재료 조회 → 기간 손익 연결.

| Story | 사용자 목적 | 자동 검사 | 사용자 화면 확인·예상 결과 |
| --- | --- | --- | --- |
| 2.1 | 귀속일별 비용 추가 | 필수값·금액·중복 의심·월계획 중복 제외·실패 | 광고비 10,000원 저장·다시 열기 유지 |
| 2.2 | 잘못된 비용 정정 | ID 유지·이전/새 집계·다른 비용·월계획 보존 | 10,000→15,000원은 기존 한 건만 정정 |
| 2.3 | 잘못된 비용 삭제 | 해당 비용 제외·다른 기록 보존·취소·실패 | 취소 시 유지, 실행 시 해당 금액만 제외 |
| 2.4 | 재료 잔량·근거 확인 | 누적 사용량·부호·단위·실사·음수·연결 오류 | 종료일 같으면 시작일과 무관하게 잔량 동일. 실측은 보존하고 충돌 시 재확인 |
| 2.5 | 기간 실적·매장 손익 확인 | 월계획 중복 제외·폐기 평가·평균·미확인·손실 | 예시 판매와 광고비 10,000원만 있는 검수 날짜의 기록 기준 손익 29,248원. 미마감 부분 기록 표시 |

완료 기준: 비용 변경이 손익에, 판매 변경이 잔량에 연결되며 5개 화면 핵심 흐름과 근거·미확인 표시를 사용자 확인한다.

## EPIC 3. 전체 기록 보호와 비공개 배포

의존성: EPIC 1·2 → 3.1 백업 → 3.2 복원 → 3.3 배포 검수.

| Story | 사용자 목적 | 자동 검사 | 사용자 화면 확인·예상 결과 |
| --- | --- | --- | --- |
| 3.1 | 전체 기록을 백업 파일로 보관 | 전체 묶음·정정값·빈칸·부호·버전·검사값·실패 | 전체 JSON 파일 다운로드. 미저장 폼을 포함했다고 표시하지 않음 |
| 3.2 | 백업 시점 전체 기록으로 복원 | 형식·매장·버전·단위·ID·용량·검사값·전체 교체·실패 | 이전 백업의 기록과 결과 재현. 손상·일부 재료 파일은 거절하고 현재 기록 유지 |
| 3.3 | 보호된 주소에서 실제로 사용 | 계산·저장·복원·빌드·접근 보호·자료 비전송·성능 | Vercel 로그인 후 핵심 흐름 실행·다시 열기 유지. 권한 없는 접근 차단 |

완료 기준: 전체 백업·복원을 재현하고 보호된 주소에서 기록을 직접 사용하며 검수 통과. 코드·계정·배포 이력은 매장 기록 백업을 대신하지 않는다.

## 시간과 제외 범위

기획 25분·화면 설계 25분·개발 125분·검사 45분·배포 20분, 총 240분을 기준으로 한다. 실제 사용한 기획·설계 시간도 포함하며 4시간을 자동으로 다시 시작하지 않는다. 시간 부족으로 저장·정확성·검사를 생략하지 않는다.

이번 요청은 EPIC 1 하나만 구현·검사한다. EPIC 2·3, 엑셀·재고 직접 입력·예측·발주·월 자동 배분·임시저장·등급 기능은 진행하지 않는다. 검수 결과는 `05_테스트결과.md`에서 자동 검사·개발자 화면 확인·사용자 확인을 분리하여 기록한다.

## 현재 작업 인계 (2026-10-12)

사용자 요청에 따라 현재 구현한 EPIC 1 범위까지만 정리하고 데모 진행으로 전환했다. U01 첫 화면은 사용자 “확인완료”로 통과를 기록했고 U02~U11은 검수 보류다. EPIC 1 전체 완료로 표시하지 않았으며 EPIC 2·3은 미착수로 유지한다. 데모 순서와 현재 구현·검수 범위는 `05_테스트결과.md`에 기록했다.
